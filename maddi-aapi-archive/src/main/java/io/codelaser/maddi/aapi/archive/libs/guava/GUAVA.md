# Guava: analysis hints and analysis state

Status: 2026-09-29. Covers the hint file next to this report (`ComGoogleCommonCollect`) and its compiled results
in `src/main/resources/.../analyzedPackageFiles/libs/guava`.

These hints state **what Guava means**, as the JDK hints do for the JDK, `VAVR.md` for vavr and
`ECLIPSECOLLECTIONS.md` for Eclipse Collections: an `ImmutableList` is an immutable container with hidden
content, its `Builder` a mutable container, `Lists` a utility class, a `Range` a value. They start from maddi's
source analysis of the library; where the computed verdict differs from the library's contract, the shadow
carries the EXPECTED annotations from the table at the end of this report, with the computed verdict kept in a
comment. The differences are the engine's distance.

## Scope: `com.google.common.collect`

The collections package: 136 public types (nested ones included: the `Immutable*.Builder`s, the
`Multiset.Entry`/`Table.Cell` contracts). It is where a client's immutability computation needs Guava's meaning;
`base` (`Preconditions`, `Strings`, `Optional`, ...) is mostly static utilities the JDK-hint conventions already
cover by default, and the other packages (`cache`, `io`, `math`, `hash`, `util.concurrent`, ...) are a later
decision. The hints are composed from the `guava:33.6.0-jre` jar, the release before the corpus's 2026-07 HEAD
checkout, decorated with the source run's verdicts: a member the release does not have carries no verdict, one it
has and HEAD renamed keeps the compiler's defaults.

## Using the hints

Guava is **side-loaded**: its results are not in `libs.jar` and not in `LoadAnalysisResults.ANALYZED_RESULTS`.
Preload them explicitly, together with the JDK hints:

```
--preload-analysis-results-dirs <archive>/analyzedPackageFiles/jdk,<archive>/analyzedPackageFiles/libs/guava
```

where `<archive>` is `maddi-aapi-archive/src/main/resources/io/codelaser/maddi/aapi/archive`. Guava is the
likely candidate for promotion into `libs.jar` (every corpus in `test-oss` but one uses it); that is a separate
decision, on evidence from a consumer's run.

## Reading a shadow

As in `VAVR.md` and `ECLIPSECOLLECTIONS.md`: the declaration comment is the library type's own header; the
annotations are the only part compiled and, for a type with an expected row, they are the EXPECTED verdict; the
second comment keeps what maddi computes and names the gap. The members follow their type
(`ComposeAnalysisHints.applyExpected`); a bare `@Container` is a MUTABLE container; `@UtilityClass` states a class
of static methods. Member rows (`type#method`) state receiver modification where the computed verdict
contradicts the method's name (mutators computed `@NotModified`, pure queries computed `@Modified`); they are
generated by `corpus/scripts/guava-expected-table.py`, not judged.

What the run says, family by family (86 of the 136 types carry an expected row; the other 50 keep their computed
verdict):

- **`Immutable*` (14 top-level types, `ImmutableCollection` to `ImmutableTable`)**: none reaches
  `@Immutable(hc = true)`; 10 compute mutable, 4 `@FinalFields`. This is G1 of `ECLIPSECOLLECTIONS.md`: the
  public class is abstract, its instances are package-private classes (`RegularImmutableList`, ...) sharing code
  with the mutable side, and a mutator that throws (`ImmutableList.add`) is still a mutator on the declared type.
  The hints state `@ImmutableContainer(hc = true) @Independent(hc = true)`.
- **The 16 nested `Immutable*.Builder`s**: 11 mutable, 5 `@FinalFields` (`ImmutableSortedMultiset.Builder`
  eventually so); expected `@Container`, the computed independence kept.
- **Utility classes (15)**: 14 compute `@Immutable` already; `MoreCollectors` computes `@FinalFields @Container`
  because its static `Collector` fields (`ONLY_ELEMENT`, `TO_OPTIONAL`) carry no independence verdict. All 15 state
  `@UtilityClass`.
- **Collection interfaces (12: `Multimap`, `Multiset`, `Table`, `RangeSet`, ...)**: all `@FinalFields @Dependent`,
  and their pure queries compute `@Modified` (`Table` 15 of them, `Multimap` 13, `RangeSet` 13, `Multiset` 10): an
  abstract method without a hint is modifying. The M2 member rows state `@NotModified` for the queries; the same
  holds on the `Forwarding*` decorators, which delegate the query (`ForwardingTable` 15, `ForwardingMultimap` 13).
- **Mutable collections (21)**: 18 compute mutable, as they should; `EvictingQueue`, `MutableClassToInstanceMap` and
  `TreeRangeMap` compute `@FinalFields` (a final delegate field). All state `@Container`; only 3 mutators compute
  `@NotModified` (M1).
- **Values**: `BoundType` (an enum) is `@Immutable`, `ComparisonChain` and `DiscreteDomain` `@Immutable(hc = true)`
  already. `Range` computes `@FinalFields @Dependent` although its two `Cut` fields are final and `Cut` computes
  `@Immutable(hc = true)`: the fields carry no unmodified verdict (not diagnosed). `ImmutableRangeSet` computes
  mutable (G1 again), `MapDifference` `@FinalFields @Container`.
- **`Forwarding*` decorators (23)**: all `@FinalFields @Dependent`, which is right: the delegate is their content.
  No expected row.
- **The jar and HEAD**: `TreeTraverser` is in the 33.6.0 jar and gone from the 2026-07 source; its shadow carries
  the compiler defaults, as the scope section says.

## How faithful the hint files are

The compiled JSON of the hints, compared with the source run on the elements the hints carry (3,982 elements,
7,190 values):

| differing values | 940 |
|---|---:|
| on types with an expected row (intended: the EXPECTED annotation and the members that follow it) | 850 |
| on the 183 member rows (M1/M2, intended) | 82 |
| encoding: a constructor's `@NotModified` and `toString`'s independence not written back, `FluentIterable`'s conditional independence flattened to `hc = true` | 8 |

The other 6,250 values round-trip unchanged. Every difference outside the expected rows is one of the eight
encoding shapes, so a consumer preloading these hints reads the source run's verdicts wherever this report does
not state otherwise.

## Regenerating

1. Onboard and build per `corpus/catalogue/guava.yml`.
2. Source run, `--analysis-results-dir <results>`, preloading `jdk`, with `--jdk-internals` as `TestGuava` does
   (`-PjvmArgs=-Dmaddi.workCeiling=30000000`).
3. `python3 corpus/scripts/guava-expected-table.py <results> <guava/src/com/google/common/collect>` (the second
   argument restricts the scope to the package's public types) and paste its rows over the table below.
4. `./gradlew :maddi-aapi-parser:composeAnalysisHints -Dorg.gradle.offline=false`
   `-Pmaddi.compose.anchor=com.google.common.collect.ImmutableList,com.google.common.util.concurrent.internal.InternalFutureFailureAccess`
   `-Pmaddi.compose.packages=com.google.common.collect`
   `-Pmaddi.compose.target=io.codelaser.maddi.aapi.archive.libs.guava`
   `-Pmaddi.compose.out=<tmp> -Pmaddi.compose.preload=<results> -Pmaddi.compose.notes=<this file>`,
   then copy the `*.java` here.
5. `:maddi-aapi-archive:compileJava`, then `:maddi-aapi-parser:compileAnalysisHints`, then
   `TestAnalysisHintsCompiler` / `TestAnalysisHintsComposer`.

Registries: `compileOnly("com.google.guava:guava:33.6.0-jre")` and `requires static com.google.common` in
`maddi-aapi-archive`; `testImplementation` in `maddi-aapi-parser`; `CompileAnalysisHints.SIDE_LOADED_LIBRARIES`
plus its inspector factory (anchored on `ImmutableList` and failureaccess's `InternalFutureFailureAccess`).
